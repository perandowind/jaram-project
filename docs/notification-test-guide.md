# 로컬 알림 수동 테스트

가입 신청과 스터디 지원 심사에서 알림이 생성되는지, 수신자의 화면이 실시간으로 갱신되는지, 연결이 끊긴 동안 생긴 알림을 다시 불러오는지 확인한다.

## 실행 환경과 계정

`home-jaram-be`와 `home-jaram-fe`가 들어 있는 상위 디렉터리에서 두 서비스를 다시 빌드한다.

```sh
docker compose up -d --build jaram-dev-be jaram-dev-fe
docker compose ps
```

브라우저에서 [로컬 사이트](http://localhost:18085)를 연다. 백엔드 포트는 `18086`이다. 백엔드와 프론트엔드가 실행 중이고 RabbitMQ가 `healthy`인지 확인한다. 이번 작업에서 사용한 로컬 DB에는 Flyway V1 baseline과 V2가 이미 등록돼 있다.

서로 다른 Chrome 프로필이나 일반 창과 시크릿 창으로 로그인 세션을 나눈다. 같은 프로필의 탭끼리는 로그인 정보를 공유한다.

| 계정 | 준비할 상태 |
|---|---|
| 회장 | 로그인 가능한 현직 회장. 가입 신청 알림 수신 확인에 사용 |
| 일반 회원 | 로그인 가능한 활동 회원. 스터디 지원과 수신자 확인에 사용 |
| 스터디장 또는 심사 권한이 있는 관리자 | 일반 회원의 스터디 지원을 승인·반려할 수 있는 계정 |
| 부회장 | 로그인 가능한 현직 부회장이 있으면 가입 신청 알림 수신을 같은 방법으로 확인 |

스터디 승인용과 반려용으로 **서로 다른 모집 중 스터디에 일반 회원 계정으로 한 건씩 지원**해 둔다. `/study`에서 **신청하기**를 사용한다. 한 건은 승인용으로, 다른 한 건은 연결 복구용으로 쓴다. 기존 미읽음 알림이 있을 수 있으므로 각 테스트 직전 배지 숫자를 적어 둔다.

## 1. 가입 신청 알림

1. 회장과 일반 회원의 창에서 각각 `/notifications`를 열어 둔다.
2. 로그아웃 상태의 별도 프로필에서 `/apply`를 열고, 로컬 DB에 등록되지 않은 학번과 신청 가능한 한양대 이메일로 가입 신청을 제출한다. 가입 심사까지 진행할 필요 없이 접수 성공 시 알림이 생성된다.
3. 새로고침 없이 회장 알림함에 **가입 승인 요청**이 나타나고 미읽음 배지가 1 증가하는지 확인한다. 부회장 창을 열어 뒀다면 같은 결과가 보여야 한다. 일반 회원 창에는 이번 알림이 없어야 한다.
4. 회장 창에서 알림 제목을 눌러 `/admin/applications`로 이동하는지 확인한다.

## 2. 스터디 승인과 읽음 처리

1. 일반 회원 창은 `/notifications`에 둔다.
2. 스터디장은 `/study`의 **내 스터디 → 관리하기**에서 승인용 신청을 승인한다. 관리자는 `/admin/studies`에서 해당 스터디의 **상세 → 인원**을 열어 승인할 수 있다.
3. 새로고침 없이 신청자의 알림함에 **스터디 지원 승인**이 나타나고 배지가 1 증가하는지 확인한다. 회장 창에는 이번 알림이 없어야 한다. 수신자 비교에는 회장이 지원하지 않은 건을 사용한다.
4. 신청자 창에서 알림의 **읽음 처리**를 누른다. 배지가 1 줄고 해당 항목의 미읽음 표시가 사라져야 한다. 제목을 누르면 `/study`로 이동한다.

## 3. 연결이 끊긴 동안 반려하고 재연결로 복구

1. 신청자 창에서 `/notifications`를 열고 Chrome 개발자 도구의 **Network** 탭에서 `/api/notifications/stream`을 찾는다. 상태가 `200`, 응답 유형이 `text/event-stream`인 요청이다. 연결이 열려 있으므로 요청이 `Pending`으로 보여도 정상이다.
2. **신청자 창에서만** Network의 네트워크 제한을 **Offline**으로 바꾼다. 기존 스트림이 끊기거나 재연결 시도가 실패하는지 확인한다. 기존 요청이 계속 열려 있으면 Chrome 개발자 도구의 요청 차단에서 `*/api/notifications/stream`을 추가하고 기존 연결의 제한 시간이 끝날 때까지 기다린다. 이 연결은 최대 60초 후 다시 연결을 시도한다.
3. 온라인 상태인 심사자 창에서 두 번째 신청을 **반려**하고 사유를 입력해 확정한다. 신청자 화면에는 아직 이번 반려 알림이 표시되지 않아야 한다.
4. 신청자 창을 **No throttling**으로 돌린다. 요청 차단을 설정했다면 해제한다. 페이지는 새로고침하지 않는다.
5. 자동 재연결로 스트림이 다시 `200`을 받고, 이어서 알림 목록과 미읽음 개수 요청이 나가는지 확인한다. **스터디 지원 반려**가 나타나고 미읽음 배지가 1 증가해야 한다. 재시도 간격은 실패를 반복하면 최대 30초까지 늘어난다.

이전 자동 검증에서는 Chrome과 백엔드 사이의 테스트 프록시에서 기존 스트림을 끊고 재접속을 일시 차단했다. 위 절차는 같은 조건을 개발자 도구로 재현한다.

## 이상이 있을 때 확인할 곳

| 관찰 결과 | 확인할 곳 |
|---|---|
| 스트림이 `401` | 로그인 세션과 스트림 요청의 Bearer 인증을 확인한다. |
| 스트림이 `404` | 최신 백엔드 이미지로 재빌드했는지 확인한다. |
| 새로고침하면 알림이 보임 | Network에서 스트림 응답과 재연결 후 목록·미읽음 개수 요청을 확인한다. |
| 새로고침해도 알림이 없음 | 신청 접수·심사 성공 여부, 수신자 조건, 백엔드 로그를 확인한다. |

```sh
docker compose logs --tail=100 jaram-dev-be jaram-dev-rabbitmq
```
